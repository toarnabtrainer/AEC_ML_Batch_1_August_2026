# ✅ Assignments on Object Oriented Programming (OOP).

### 🔰 Here are 5 hands-on assignments aligned with the topics: classes/objects, constructors, variables and methods, attributes/access control, inheritance, operator overloading, and abstraction.

## 🔵 Assignment 1 — Employee Management Using Classes and Objects

Create an `Employee` class to maintain basic employee information.

**Tasks:**

* Create instance attributes such as `employee_id`, `name`, `department` and `salary` using `__init__()`.
* Add instance methods to display employee details and calculate annual salary.
* Create a class variable such as `company_name` shared by all employees.
* Create at least 5 employee objects and display their information.

**Expected Output:** Employee details demonstrating **classes, objects, constructors, instance variables, class variables and instance methods**.

---

## 🔵 Assignment 2 — Banking System with Different Types of Methods

Create a `BankAccount` class representing customer bank accounts.

**Tasks:**

* Initialize `account_number`, `customer_name` and `balance` through the constructor.
* Create instance methods for `deposit()`, `withdraw()` and displaying account information.
* Implement one `@classmethod` and one `@staticmethod` for suitable banking operations.
* Use `isinstance()`, `hasattr()`, `getattr()` and `setattr()` on the created objects.

**Expected Output:** A working banking example demonstrating **instance methods, class methods, static methods and built-in object/attribute functions**.

---

## 🔵 Assignment 3 — Student Record with Encapsulation and Dynamic Attributes

Create a `Student` class to manage student information.

**Tasks:**

* Maintain attributes such as student ID, name and marks, including at least one **private attribute** using `__`.
* Provide appropriate methods to access/update the private information.
* Dynamically add an attribute such as `course` or `grade` using `setattr()` and retrieve it using `getattr()`.
* Demonstrate `hasattr()` and Python **name mangling** for a private attribute.

**Expected Output:** Student records demonstrating **private members, dynamic attributes, attribute-related functions and name mangling**.

---

## 🔵 Assignment 4 — Employee Hierarchy Using Inheritance

Design an employee hierarchy containing a base `Employee` class and suitable derived classes such as `Manager`, `Developer` and `Trainer`.

**Tasks:**

* Implement **single inheritance** with common attributes and methods in the base class.
* Extend the design to demonstrate **hierarchical inheritance** using multiple employee types.
* Create an example of **multiple inheritance** using two suitable base classes.
* Examine the **Method Resolution Order (MRO)** in the multiple-inheritance example.

**Expected Output:** A class hierarchy demonstrating **single, hierarchical and multiple inheritance along with MRO**.

---

## 🔵 Assignment 5 — Shape/Calculation System Using Abstraction and Operator Overloading

Create an application demonstrating advanced OOP concepts from the notebook.

**Tasks:**

* Create an abstract base class using `ABC` and `@abstractmethod`, and implement the abstract method in suitable derived classes.
* Create objects of the derived classes and demonstrate their implementations.
* Create a suitable class to overload the `+` operator using `__add__()`.
* Similarly demonstrate subtraction using `__sub__()` and test the overloaded operators with multiple objects.

**Expected Output:** A working application demonstrating **abstract classes, abstract methods, inheritance and operator overloading**.

### Recommended progression

I would use **Assignments 1–2 for basic/intermediate practice**, **Assignments 3–4 for encapsulation and inheritance**, and **Assignment 5 as the advanced OOP exercise**.

Together, the five assignments follow the learning sequence of your notebook:

**Class & Object → Constructor → Instance/Class/Static Members → Dynamic & Private Attributes → Inheritance & MRO → Operator Overloading → Abstract Classes**

This should give participants enough hands-on work without introducing major OOP concepts beyond what was taught in the notebook.
